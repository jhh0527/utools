--------------------------------------------------------------------------------

【작품 메타 — 교체 시 필수 기입】
- 작품명: 검신귀환록
- 출처: characters.md (나이·설정 우선) + art/character_sheet_prompt.md (비주얼)
- 주인공 영문명: Jin Muhan
- 주인공 LOOK 변형: 입문≈15 / 기본≈19(하산·이대) / 전생≈35 최후 — 나이 숫자 구간(18-to-19) 금지, 하나로 고정

★★★ 0-K. 인물 상태 일관성 (공통 규칙 — 교체하지 않음) ★★★
--------------------------------------------------------------------------------
목적: 동일인물이 같은 이야기 “지금”에 있을 때
      · Face Identity(얼굴)는 칸마다 동일
      · 머리·옷·상처·소품은 State Layer로만 바꾸고, 바꾼 뒤에는 복사 유지
      (작품이 바뀌어도 이 규칙은 동일)

【이층 구조】
1) Face Identity — 눈·코·입·턱·피부·체형·기본 표정 골격. **절대 칸마다 바꾸지 않음**
2) State Layer — 머리 묶음·옷 손상·피·붕대·상처·무기 상태.
   대본이 명시할 때만 §0 프리셋(또는 동등 영문 상태키)으로 갱신 → 이후 현재 칸에 **동일 복사**

【적용】
- **동일인물 + 동일 시점(현생 현재 타임라인)** 의 모든 칸
- 작성법:
  1) 매칭표에 타임라인: `현재` | `회상/전생` | `꿈/환상`
  2) `현재`면 — Face Identity + 나이 LOOK + **상태키 프리셋**을 프롬프트에 넣음
  3) 앞 칸과 대본 상태 변화가 없으면 상태키·State 문구 **글자 단위 동일 복사**
  4) 대본이 피·찢긴 옷·풀린 머리·상처를 말할 때만 상태키 갱신 (예: `Jin≈19|base` → `Jin≈19|blood_robe`)
  5) 장면·포즈·배경·(허용된) 감정 눈빛은 달라도 됨. Face는 고정 · State만 표 따름

【상태키 형식】
`이름≈나이|프리셋` · 복수: `Jin≈19|blood_robe; Baek≈19|base`
예: Jin≈19|base · Jin≈19|battle_torn · Jin≈19|blood_robe · Jin≈19|wounded_shoulder · Jin≈19|hair_loose

【예외 — State 유지 불필요】
- 과거 회상, 전생, 기억, 꿈·환상 — §0 전생/과거 LOOK 사용 가능
- 회상·전생 칸이 끝나고 **다시 현재** → 직전에 쓰던 **현재 상태키**로 복귀

【무효 예시】
✗ 현재 시점에서 대본에 옷·상처 변경 없이 칸마다 복장·색·머리가 바뀜
✗ 대본에 상태 변화 있는데 상태키를 안 바꾸고 base만 유지
✗ Character Anchor로 머리·옷을 “절대 고정”해 대본상 피·찢김을 무시
✗ 현재 칸에 전생 LOOK(흉상·찢긴 옷)을 임의로 섞음
✗ 회상 상태를 현재 복귀 후에도 유지

【유효 예시】
✓ 현재 연속 칸: Face 동일 + 상태키 `Jin≈19|base` 동일 복사
✓ 대본「도포에 피」→ 그 칸부터 `Jin≈19|blood_robe` → 이후 현재 칸도 blood_robe 복사
✓ 회상 칸만 전생 LOOK → 다음 현재 칸은 직전 현재 상태키로 복귀

- **마지막 SRT 종료초(E)**: 마지막 SRT 항목의 종료 시간을 초 단위로 변환
- **구간 길이(L)**: L = E − F

3-2. 타임스탬프 생성 (= 씬 라벨 XXX)

【기본 간격: 20초 (절대 규칙)】
- 타임스탬프: F, F+20, F+40, F+60, …
- 총 타임스탬프 개수 = floor(L / 20) = floor((E − F) / 20)
- ★ 10·15·30초 간격 금지. 반드시 20초. ★

【120초(2분) 배치 — 순차 생성】
- 배치 1개당 최대 6장 (20초 × 6)
- 배치 순서대로 매칭·프롬프트 생성 (총 개수 = floor(L/20) 유지)

★★★ 위 타임스탬프 T가 곧 출력 라벨이다.
예: T=0 → `SRT_000:` · T=140 → `SRT_140:` (140초 이미지). ★★★

3-3. 마지막 이미지 제한
- 마지막 매칭 SRT 항목 번호 ≤ (전체 SRT 항목 수 − 5)
- 초과 시 해당 타임스탬프는 프롬프트 생성 안 함

3-4. 총 필요 이미지 수
- 공식: **floor((E − F) / 20)**


4. 타임스탬프 T → 구간 대본 매칭 (절대)
--------------------------------------------------------------------------------

목적: `SRT_XXX` 라벨·장면이 **영상 XXX초**에 붙게 한다.
시청자가 XXX초에 듣는 자막 = 그 초 라벨(`SRT_XXX`)의 이미지.
예: `SRT_140` = 140초 이미지 = 구간 [140, 160) 대본.

4-1. 기본 규칙
- 1번 SRT 항목부터 매칭 대상
- 각 타임스탬프 T에 출력 라벨 `SRT_{T}:` **1개** (T와 라벨 숫자 동일)
- 구간 [T, T+20)에 겹치는 SRT 큐들로 **대본앵커**만 만든다 (라벨은 T 고정)

4-2. 매칭 알고리즘 (각 타임스탬프 T)

단계 1: 시작시간 ≤ T 인 SRT 중, 아직 미선택 · 시작시간이 **가장 큰** 항목을 **앵커 후보**로 선택
단계 2: 단계 1 실패 시 → 시작시간 > T 인 미선택 중 시작시간이 **가장 작은** 항목 선택
단계 3: 후보 큐 + [T, T+20)에 시작·겹치는 큐의 한글을 모아 대본앵커 작성
※ 라벨은 항상 T. 후보 큐 시작초(예: 149)를 라벨로 쓰지 말 것.

4-3. ★★★ 라벨 = 타임스탬프 T (영상 초) ★★★
- 출력 라벨: `SRT_{T, 최소 3자리}:`
  · T=0 → `SRT_000:`
  · T=20 → `SRT_020:`
  · T=60 → `SRT_060:`
  · T=140 → `SRT_140:`  (= **140초 이미지**)
  · T=1080 → `SRT_1080:`
- ✓ `SRT_000: SRT_020: SRT_040: … SRT_140: …` 처럼 20초 격자 연속 = **정상**
- ✗ `SRT_026: SRT_058: SRT_149:` 처럼 큐 시작초(floor)만 라벨로 쓰면 **무효**
  (구버전·프로그램 격자 밖 초 — GUI는 생성 목록에 넣지 않음)

4-4. ★★★ 장면 내용 = [T, T+20) 대본만 (표시 구간 동기) ★★★

★★★ 이미지 표시 구간 — SRT_XXX 와 대본 일치 ★★★
- 라벨 T = 타임스탬프 → 출력 `SRT_T:` (예: 140 → `SRT_140:`)
- 이미지는 대략 **T초 ~ min(T+20, 다음라벨)** 동안 보인다
- **그 구간에 시작·겹치는 모든 SRT 한글 자막** = 이 이미지의 유일한 사건 출처
- 공식: `SRT_T` 프롬프트 사건 ⊆ 구간 [T, T+20) 대본
- ✗ 구간 밖(다음·이후) 대본의 인물·사건을 넣으면 시청자는 지금 대본을 듣는데 다른 이미지가 나와 **불일치 → 무효**

작성 절차 (필수 순서 — 건너뛰기 금지):
1. T 확정 → 라벨 `SRT_T:` (§4-2로 구간 대본 수집)
2. SRT에서 **시작시간이 [T, T+20) 인 큐 + T를 덮는 큐**의 한글을 전부 모은다
3. 그 한글만으로 **대본 앵커** 한 문장 (한글, 매칭표용)
   예: §0-X 【대본 앵커 작성 예시】 참조
4. 앵커 → 시점 판정(`현재`/`회상`/`전생`/`꿈`) → 영문 주체·객체·행동·장소. 앵커에 없는 것 추가 금지
5. §0 LOOK은 앵커에 그 인물이 있을 때만. 시점=`현재`면 Face Identity + §0-K 상태키(대본 변화 없으면 앞 칸 복사)
   Jin Muhan이면 LOOK·State 뒤 Character Anchor(얼굴만) 첨부. 기본 표정은 calm unreadable만
6. ✗ 금지: 장 줄거리 균등 배치 · 다음 칸 대본 선행 · “나중에 나올 장면” 미리 그리기
   · ✗ 대본 변화 없이 칸마다 복장·상처·머리를 다르게 쓰기 · ✗ 대본 변화를 상태키에 반영하지 않기

【대본↔SRT_XXX 불일치 — 전부 무효】
✗ 매칭표 앵커와 다른 인물·사건을 프롬프트에 넣음 (§0-X 무효 예시 참조)
✗ 매칭표 앵커와 영문 프롬프트 사건이 다름
✗ 현재 시점 동일인물인데 대본 변화 없이 칸마다 옷색·상처·머리 상태가 다름
✗ 대본에 피·찢김이 있는데도 상태키를 base로 유지하거나, 반대로 대본 없이 blood_robe로 임의 변경
✗ 라벨 숫자 ≠ T (큐 시작초를 라벨로 씀)

【자기검증 — 각 줄 출력 직전】
  (a) 라벨 XXX == 타임스탬프 T (20초 격자) ?  (예: 140초 칸이면 SRT_140)
  (b) 매칭표에 이 줄의 대본 앵커가 있는가 ?
  (c) 영문 프롬프트 사건 == 그 앵커와 동일 ? (다음 구간 사건 없음 ?)
  (d) 시점=현재이면 Face 동일 · 상태키 == 앞 현재칸(또는 대본 변화 시 갱신된 프리셋) ? (회상·전생은 스킵)
하나라도 아니면 다시 작성.

3) 이미지 내용 요약 (각 생성 이미지 간략 기술 — 한글 한 줄)
4) 검증 결과

★ 매칭표 없이 씬 트랙만 출력하면 무효. 표의 대본 앵커 ↔ 영문 프롬프트가 같아야 한다. ★
★ 씬 트랙 작성 후 **반드시** 이미지 내용 요약을 출력한다. 생략 시 무효. ★

12-3. ★★★ 씬 트랙 형식 (무협 전용 — 절대 준수) ★★★

★★★ 핵심: 라벨 = 매칭표의 T(=영상 초). 프롬프트 = 그 줄 대본앵커의 영문 시각화만. ★★★

형식:
SRT_XXX: Chinese wuxia manhua illustration of [English scene…], Chinese wuxia manhua (중국 무협 만화) style illustration, [§6 통합 스타일…]
★ 콜론 뒤 프롬프트 본문에 한글·`Korean text` 힌트 없음
★ 매칭표에 없는 라벨·사건 금지
★ §6 끝에 반드시 `16:9 aspect ratio` 포함 (정사각·9:16·세로 비율 금지)

올바른 예시:
- 형식·라벨·스타일만 여기서 확인하고, **장면·인물 문구는 §0-X 【씬 트랙 올바른 예시 요약】+ §0 LOOK** 을 쓴다.
- 라벨 = 20초 격자 T. 예: `SRT_140:` = 140초 이미지.
- `[§6…]` 축약 시에도 실제 출력에는 **16:9 aspect ratio** 문구를 생략하지 않는다.

SRT_000: Chinese wuxia manhua illustration of [§0 LOOK + §0-X 장면], [Jin이면 Character Anchor], Chinese wuxia manhua (중국 무협 만화) style illustration, [§6…], 16:9 aspect ratio, ultra high resolution digital manhua art
SRT_020: Chinese wuxia manhua illustration of [§0 LOOK + §0-X 장면], [Jin이면 Character Anchor], Chinese wuxia manhua (중국 무협 만화) style illustration, [§6…], 16:9 aspect ratio, ultra high resolution digital manhua art
SRT_140: … (140초 이미지. 1000초 이상은 자릿수 그대로) … 16:9 aspect ratio …

각 프롬프트는 아래 중 최소 2개 이상을 명시적으로 포함해야 한다. (모두 영문)
  1. 매칭표 대본앵커의 핵심 행동 (English action)
  2. 매칭표 대본앵커의 핵심 객체 (English object)
  3. 매칭표 대본앵커의 핵심 숫자·고유명사 (romanized / English, no Hangul)
조건 미충족·앵커와 불일치 시 프롬프트 무효. 한글이 씬 트랙 본문에 있으면 무효.

잘못된 예시 (전부 금지):
✗ SRT_000.png {…}                 (.png + 중괄호 — image.md 형식 금지)
✗ SRT_000.png Chinese wuxia…      (.png 사용 금지)
✗ SRT_000 {Chinese wuxia…}        (중괄호 사용 금지)
✗ 2. Chinese wuxia…               (SRT 번호 사용)
✗ SRT_2: Chinese wuxia…           (zero-padding 누락)
✗ SRT_026: / SRT_058: / SRT_149: … (큐 시작초를 라벨로 씀 — T와 다르면 금지)
✗ 매칭표 없이 씬 트랙만 출력
✗ 매칭표 앵커와 다른 인물을 프롬프트에 넣음 (§0-X 무효 예시)
✗ 장 줄거리를 시간축에 균등 배치한 스토리보드 (미래·다음 대본 선행 금지)
✗ … of 한글인물명 … Korean text "…" …  (한글·힌트 — 깨짐 유발)
✗ … wearing Korean hanbok / jeogori …  (한복 금지 — Chinese hanfu만)

12-3b. ★★★ 이미지 내용 요약 (씬 트랙 직후 · 필수) ★★★

씬 트랙(영문 프롬프트)을 모두 쓴 뒤, **각 이미지가 무엇을 그리는지** 한글로 간략히 기술한다.
시청·검수용. 매칭표 대본앵커와 동일 사건이어야 하며, 긴 줄거리·다음 장면 예고 금지.

형식:
================================================================================
이미지 내용 요약
================================================================================
SRT_XXX: (한글 한 줄 — 인물·행동·장소·핵심 사건만, 15~40자 권장)

예시:
SRT_020: 진무한, 화산 남봉 매화 아래 이대 승격 직후

SRT_1080: …

규칙:
- 행 수 = 씬 트랙 프롬프트 수 (라벨 1:1)
- 라벨은 씬 트랙과 동일 (`SRT_XXX:`)
- 본문은 **한글** (영문 프롬프트 재나열 금지)
- 매칭표 대본앵커와 사건 불일치 시 무효
- ✗ 프롬프트 전문 복사 · ✗ 대사 전문 · ✗ 다음·이후 구간 내용

13. 주의사항 (필수 준수)
--------------------------------------------------------------------------------

13-1. 입력은 SRT 파일이다. 대본이 아니다.

13-2. 씬 트랙에는 대본/대사 원문을 넣지 않는다.
   ○ 올바른 출력: SRT_140: Chinese wuxia manhua illustration of …
   ○ 허용: 영상 분석 **매칭표**의 대본앵커(한글 한 문장) — 프롬프트 작성용 고정
   ✗ 잘못된 출력: 씬 트랙에 한글 대사 전문
   ✗ 잘못된 출력: SRT_012.png {…}

13-3. ★★★ 씬 트랙 라벨 = 영상 초(20초 격자) ★★★
   라벨 XXX = 타임스탬프 T, 형식 `SRT_XXX:` (콜론 필수, .png·{} 금지)
   `SRT_140:` = **140초 이미지**. 내용은 구간 [140, 160) 대본.
   정상 출력 라벨은 000,020,040,…,140처럼 20초 격자. ✗ 026,058,149(큐 시작초) 금지.

13-4. ★★★ 이미지 무문자 · 프롬프트만 영문 · 한복 금지 ★★★
   이미지 위 글자 절대 금지 (영문·중문·한글·일본어). 인물명은 §0 영문 이름만(프롬프트용).
   매칭표 대본앵커만 한글 허용. ✗ `English text` / `Chinese text` / `Korean text` 금지.
   제목·자막·대사는 SRT 번인·후편집으로만.
   복식: Chinese hanfu만. ✗ hanbok·한복·저고리·치마·갓.

13-5. SRT의 경지·검법·숫자·고유명사는 영문 시각 요소로 프롬프트에 반영한다.

13-6. 1번 SRT 항목부터 매칭 대상이다.

13-7. 마지막 매칭 SRT 번호 ≤ (전체 SRT 수 - 5).

13-8. ★★★ 말풍선·풍선도움말 절대 금지 ★★★
   speech bubble / comic balloon / tooltip / callout / 대사 박스 이미지에 금지.
   saying·speaking 등 트리거 동사 금지. 표정·포즈로만 표현.

13-9. ★★★ 간격은 반드시 20초 · 120초 배치 순차 생성 ★★★

13-10. 등장인물은 §0 Character Bible LOOK만 사용 (§0 작품 메타의 영문 이름), Chinese wuxia manhua only.

13-10b. ★★★ 동일인물·동일시점 상태 일관 (§0-K) ★★★
   Face Identity(얼굴)는 칸마다 고정. State Layer(머리·옷·상처·소품)는 `이름≈나이|프리셋` 상태키로만 변경.
   대본이 상태를 바꿀 때만 프리셋 갱신 → 이후 현재 칸에 동일 복사. 미변화면 앞 칸 상태키 그대로.
   과거 회상·전생·꿈·환상은 State 유지 불필요. 현재로 돌아오면 직전 현재 상태키로 복귀.
   ✗ 대본 없이 머리·옷을 칸마다 바꾸기 · ✗ Character Anchor로 머리·옷을 절대 고정해 대본 변화를 무시
   ✗ 현재 칸에 전생 LOOK(찢긴 옷·흉상 등)을 임의로 섞지 말 것.

13-11. ★★★ SRT_XXX = 그 초 대본 (스토리보드·다음 대본 선행 금지) ★★★
   매칭표 완성 → 씬 트랙. 각 `SRT_XXX`는 표의 대본앵커([XXX, XXX+20) 한글)만 그린다.
   장 후반 사건을 앞 칸에 미리 배치하지 않는다 (§0-X 선행 배치 금지 예시).
   시청자가 XXX초에 듣는 대본 ≠ 이미지 사건 이면 무효.

13-12. 최종 출력물은 오직 ①영상 분석 결과(매칭표 포함) ②씬 트랙 ③이미지 내용 요약 ④검증 결과 만.
    → 첫 출력 문자는 반드시 "====" 로 시작.
    → 인사말·안내문·부가 설명 금지.
    → ★ 씬 트랙 직후 이미지 내용 요약(한글 한 줄×N) 생략 금지 ★

13-13. 라벨 숫자(타임스탬프 T) 오름차순 출력.

13-14. ★★★ 이미지 생성(씬 트랙) 후 내용 간략 기술 ★★★
   각 `SRT_XXX` 영문 프롬프트에 대응하는 이미지를 **한글 한 줄**로 기술한다 (§12-3b).
   인물·행동·장소·핵심 사건만. 매칭표 대본앵커와 같아야 한다.


14. 내부 처리 프로세스 (출력 금지 - 내부 전용)
--------------------------------------------------------------------------------

[선행] SRT 파싱 → F/E/L 계산 → 20초 타임스탬프 T 생성 (= 라벨)
→ 각 T에 대해 라벨 `SRT_{T}:` 고정 (예: T=140 → SRT_140 = 140초 이미지)
→ §4로 구간 [T, T+20) SRT 한글 수집 → 대본 앵커 → 시점(현재|회상|전생|꿈) 판정 → 매칭표 행 작성
→ 시점=현재면 Face Identity + 상태키 확정(앞 칸 복사 또는 대본 변화 시 프리셋 갱신) → 매칭표 상태키 기록
